# BM25 Retrieval

**Module:** `src/marley/retrieval/`
**Implementation:** `bm25.py`
**Library:** `rank-bm25` (Okapi BM25)

Sparse retrieval based on exact term matching. For the overall retrieval architecture, class hierarchy, and shared interface, see [overview.md](overview.md).

---

## Theoretical Background

BM25 (Best Matching 25) is a probabilistic ranking function from the Okapi family of retrieval models (Robertson et al., 1995). It estimates the relevance of a document to a query based on term frequency (TF), inverse document frequency (IDF), and document length normalization.

The BM25 scoring function for a query `Q` containing terms `q_1, ..., q_n` and a document `D` is:

```
BM25(D, Q) = sum( IDF(q_i) * (f(q_i, D) * (k1 + 1)) / (f(q_i, D) + k1 * (1 - b + b * |D| / avgdl)) )
```

where `f(q_i, D)` is the term frequency of `q_i` in `D`, `|D|` is the document length, `avgdl` is the average document length, and `k1` (default 1.5) and `b` (default 0.75) are hyperparameters controlling term saturation and length normalization respectively.

BM25 is a **sparse retrieval** method: it operates on exact term matches and cannot capture synonyms or paraphrases. However, it is highly effective for domain-specific terminology (e.g., `§23`, `LP`, `Regelstudienzeit`) where exact keyword matching is desirable. The simple whitespace tokenization used in MARley preserves these domain tokens without requiring language-specific stopword lists or stemming.

MARley uses the `rank-bm25` library, which implements the Okapi BM25 variant with default hyperparameters (`k1=1.5`, `b=0.75`). These defaults are well-established and generally robust across domains (Robertson & Zaragoza, 2009).

## Architecture

For the full retriever class hierarchy and shared interface, see [overview.md](overview.md).

```
BM25Retriever(Retriever)
├── _tokenize(text) → lowercase whitespace splitting
├── index(corpus) → validate + tokenize + build BM25Okapi
├── retrieve(query, k) → score all docs, return top-k (score > 0)
└── size → number of indexed chunks
```

BM25Retriever is a leaf retriever — it owns and manages its own in-memory index. No external storage or persistence is required (unlike VectorRetriever). The index is built from scratch on each `index()` call.

---

## Implementation

### Text Preprocessing

Tokenization uses lowercase whitespace splitting:

```python
def _tokenize(text: str) -> list[str]:
    return text.lower().split()
```

This simple approach:

- Preserves special tokens like `§23`, `CS 699`, `LP`
- Requires no external stopword lists or language models
- Is fully reproducible and deterministic

### Input Validation

Before indexing, `validate_corpus()` checks that every dict in the corpus contains the required keys (`chunk_id`, `text`, `metadata`). Missing keys raise a `ValueError` with a descriptive message. This shared validation (from `src.marley.models.retrieval`) is used by all retriever implementations.

### Index Building

1. Load chunks from JSON via `load_chunks(path)` (from `src.marley.models.retrieval`)
2. Validate corpus structure via `validate_corpus()`
3. Tokenize each chunk text
4. Build BM25Okapi index over tokenized corpus

### Retrieval

1. Tokenize the query
2. Compute BM25 scores for all documents
3. Sort by score descending
4. Return top-k results with score > 0

### Score Scale

BM25 scores are unbounded, typically ranging from 0 to ~100+ (higher means more relevant). The exact magnitude depends on corpus size, document lengths, and query-document overlap.

### Zero-Score Filtering

Results with BM25 score <= 0 are excluded. This occurs when query terms do not appear in a document or have zero IDF weight.

## Usage

```python
from src.marley.retrieval import BM25Retriever, load_chunks

# Load and index
chunks = load_chunks("data/chunks/stpo-chunks.json")
retriever = BM25Retriever()
retriever.index(chunks)

# Retrieve
results = retriever.retrieve("master thesis credits", k=5)
for r in results:
    print(f"{r.chunk_id}: {r.score:.2f}")
```

### Loading Multiple Knowledge Bases

```python
stpo = load_chunks("data/chunks/stpo-chunks.json")
faq_stpo = load_chunks("data/chunks/faq-stpo-chunks.json")

# Combined index
retriever = BM25Retriever()
retriever.index(stpo + faq_stpo)
```

BM25 hyperparameters (`k1`, `b`) use the rank_bm25 defaults (k1=1.5, b=0.75).
